# Notes の更新ガイド

個人ブログ（`_posts/`）とは別に、継続的に更新するための調査ノート集です。

- 公開一覧：`/notes/`
- 記事：`_notes/*.md`（1テーマ = 1ファイル）
- レイアウト：`_layouts/note.html`
- ナビゲーション：`_includes/header.html`

## いつもの更新方法

1. GitHub上で該当する `_notes/*.md` を開いて編集する。
2. 先頭の `updated_at` を編集日（YYYY-MM-DD）に変更する。
3. `status` を `調査中` / `要再確認` / `検証済み` などに更新する。全体が未検証なら `検証済み` にしない。
4. 本文の該当箇所と、必要なら「未検証事項」「一次情報」や「更新履歴」を修正する。
5. PRを作成して確認し、マージする。価格・規約など変動する情報は、確認日と公式URLを残す。

## 新しいテーマを増やす

`_notes/07-new-topic.md` のように番号付きMarkdownファイルを追加する。以下を先頭に記載する：

```yaml
---
title: "新しいテーマ"
description: "短い説明。"
order: 7
category: "動画・広告"
updated_at: "2026-11-05"
status: "調査中"
---
```

`order` は一覧の表示順、`updated_at` は最終修正日です。
URLはファイル名から `/notes/07-new-topic/` になります。公開後にファイル名を変えるとURLも変わるので注意してください。

## 本文の編集ルール

- AIに文章をまとめてもらってもよい。ただし、内容を検証したかどうかは区別する。
- 自分で測定していない比較や、動作確認していない機能は「未検証」とする。
- ツールの料金・無料枠・商用ライセンスは**公式リンクと確認日**を併記する。
- 根拠が不十分なことは断定しない。実際に確認した内容は「確認済み」と区別する。
- 公開情報だけを扱い、仕事の非公開資料・顧客情報・社内情報は書かない。
- 大幅な変更は本文末の「更新履歴」に追記すると、あとで判断しやすい。

サイトの名前は **Notes** です。AIを使ったかどうかではなく、調査した知識を後で使える形に整理していくことを主題にしています。

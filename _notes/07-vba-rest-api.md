## やりたいこと

VBAからREST APIを呼び出す処理を、利用箇所ごとに書き直さず、**1つの共通関数**として扱えるようにする。

呼び出し先に応じて、HTTPメソッド・プロキシ・クエリパラメータの有無を切り替えたい。

## 必要な機能

| 項目 | 対応する内容 |
| --- | --- |
| 実行環境 | VBA（Excelなど） |
| HTTPメソッド | GET / POST / PUT / DELETE |
| ネットワーク | プロキシ経由と直接接続の両方 |
| URL | APIのエンドポイントを引数で指定 |
| クエリパラメータ | 指定する／しないを選べる |
| リクエスト本文 | POST・PUTなどで必要に応じて指定 |
| 戻り値 | ステータスコードとレスポンス本文を取得する |
| 共通化 | 呼び出し元から関数として利用する |

## 関数のインターフェース案

関数名は仮に `SendApiRequest` とする。**以下は実装済みコードではなく、引数の設計例**。

```vb
' インターフェース案（擬似コード）
SendApiRequest( _
    method, _
    endpoint, _
    queryParams, _
    requestBody, _
    useProxy, _
    proxyAddress _
)
```

- `method`：GET / POST / PUT / DELETE のいずれか。
- `endpoint`：ベースとなるURL。
- `queryParams`：省略可能なクエリパラメータ。未指定ならURLに追加しない。
- `requestBody`：必要な場合だけ渡すリクエスト本文。
- `useProxy`：プロキシを使うかどうか。
- `proxyAddress`：プロキシ使用時の接続先。直接接続では使わない。

レスポンスは文字列だけでなく、HTTPステータスコードやエラー情報も呼び出し元で参照できる形にしたい。

## 処理の流れ

1. HTTPメソッドが許可されているか確認する。
2. クエリパラメータがあればURLエンコードしてエンドポイントに付加する。なければ元のURLを使う。
3. プロキシを使用する場合は接続先を設定し、使用しない場合は直接接続を選ぶ。
4. HTTPリクエストを開き、必要なヘッダーと本文を設定して送信する。
5. レスポンスのステータスコード・本文を受け取り、呼び出し元に返す。

### HTTPメソッド別の使い方

| メソッド | 主な用途 | 本文 |
| --- | --- | --- |
| GET | データの取得 | 通常は送らない |
| POST | データの送信・作成 | API仕様に応じて指定 |
| PUT | データの更新・置換 | API仕様に応じて指定 |
| DELETE | データの削除 | API仕様に応じて指定 |

実際にどのメソッド・ヘッダー・本文が必要かはAPIごとの仕様に従う。

### クエリパラメータ

例えば、ベースURLが `https://example.com/api/items` なら、任意のパラメータを付けて `https://example.com/api/items?category=book&page=2` のように呼び出す。

パラメータがない場合は `https://example.com/api/items` のまま送る。日本語や空白、記号を含む値は適切なエンコードが必要になる。

### プロキシ設定

社内ネットワークなどではプロキシ経由の接続が必要な場合がある。一方、接続環境によってはプロキシを通さずにアクセスしたい。

関数の引数で切り替えられるようにし、**プロキシ指定の有無と、直接接続かどうかを混同しない**ようにする。認証が必要なプロキシや、Windowsの既定設定を使用するケースは別途確認する。

## 実装時の注意点

- VBAのHTTP通信手段として `WinHttp.WinHttpRequest.5.1` などを検討する。プロキシ設定の詳細は利用するコンポーネントに依存する。
- タイムアウトと通信失敗時の例外処理を入れ、HTTP 4xx / 5xx も正常応答（2xx）とは区別する。
- JSONを扱う場合は `Content-Type` や文字コード、必要に応じたJSON解析を考慮する。
- APIキーやパスワードをソースコードに直書きしない。個人情報・認証情報をURLのクエリに含めない。
- URLの既存の `?`、複数のクエリ値、重複キー、特殊文字、プロキシ未使用時の挙動をテストする。
